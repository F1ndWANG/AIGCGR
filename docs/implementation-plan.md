# LifeRec 实施计划

## 第一步：项目骨架

实现内容：

- 创建 `backend/`、`frontend/`、`data/`、`docs/` 目录。
- 添加 README、架构文档、数据说明和隐私安全说明。

得到效果：

- 项目具备开源仓库的基本结构。
- 后续模块可以按场景独立扩展。

使用方法：

- 采用前后端分离结构。
- 后端负责推荐逻辑和 API。
- 前端负责用户交互和推荐结果展示。

## 第二步：示例数据

实现内容：

- 用户画像数据。
- 近期饮食记录。
- 餐厅数据。
- 菜品数据。
- 生活商品数据。
- 旅行目的地数据。

得到效果：

- 不依赖真实第三方平台，也能完整演示推荐流程。
- 数据结构清晰，后续可替换为真实 API 或数据库。

使用方法：

- 使用 JSON 文件作为 MVP 数据源。
- 通过标签连接用户偏好、健康约束和推荐对象。

## 第三步：推荐核心

实现内容：

- 意图识别：判断用户需求属于饮食餐厅、生活购物或旅行规划。
- 健康状态分析：根据近期饮食记录识别高油、高盐、蔬菜少、蛋白不足。
- 候选生成：根据场景生成餐厅、商品或目的地候选。
- 推荐排序：按偏好、健康、预算、距离和上下文打分。
- 推荐解释：生成推荐理由和行动计划。

得到效果：

- 系统不只是聊天，而是具备明确推荐链路。
- 每个推荐都有分数、标签、理由和可执行建议。

使用方法：

- 第一版采用规则排序，保证可解释和可控。
- 后续可替换为向量检索、语义 ID 或深度推荐模型。

## 第四步：后端 API

实现内容：

- `GET /api/health`：服务健康检查。
- `GET /api/dataset/summary`：示例数据统计。
- `POST /api/recommend`：统一推荐入口。

得到效果：

- 前端和第三方客户端可以通过统一接口调用推荐能力。
- 推荐场景可以由系统自动识别，也可以由用户指定。

使用方法：

- 使用 FastAPI 和 Pydantic。
- 输出统一 JSON，便于前端展示和测试。

## 第五步：前端工作台

实现内容：

- 场景切换：自动识别、饮食餐厅、生活购物、旅行规划。
- 自然语言输入。
- 快捷示例 Prompt。
- 推荐结果卡片。
- 健康上下文、意图识别和行动计划展示。

得到效果：

- 用户可以直接体验 AI 生活推荐流程。
- 推荐结果从列表升级为“解释 + 计划 + 可执行建议”。

使用方法：

- 使用原生 HTML/CSS/JavaScript。
- 通过 `fetch` 调用 FastAPI。
- 设计风格偏生活规划工具，避免普通聊天机器人形态。

## 第六步：验证

实现内容：

- Python 编译检查。
- 推荐核心样例测试。
- FastAPI TestClient API 测试。
- 本地启动后端和前端静态服务。

得到效果：

- 确认 MVP 可以运行。
- 确认饮食、购物、旅行三个核心样例可以命中正确场景。

使用方法：

- `python -m compileall backend`
- FastAPI TestClient 调用 `/api/recommend`
- 本地访问 `http://127.0.0.1:5173`

## 后续版本

- `v0.2`：动态位置推荐，接入地图/地点 Provider，并根据当前位置计算距离。
- `v0.3`：接入真实 LLM，用 JSON Schema 强化意图识别和解释生成。
- `v0.4`：加入向量检索，支持餐厅、商品和景点的语义召回。
- `v0.5`：加入用户反馈学习，更新短期偏好。
- `v0.6`：插件化地图、电商、外卖、天气和日历能力。
